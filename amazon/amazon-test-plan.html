Test Plan

Test Strategy for Authentication, Search, Cart, and Accessibility

Requirements Test Plan Test Cases Automation Bug Reports
Objective
Independently verify core customer journeys on Amazon.com against documented requirements (REQ-AMZ-01 to REQ-AMZ-04), report deviations as defects or observations, and extend selected manual test cases into automated regression checks.
Scope
In scope:
  • Authentication — valid login, invalid password handling (TC-AMZ-001, 002)
  • Search — valid query results, no-results handling (TC-AMZ-003, 005)
  • Cart — persistence across sessions, maximum quantity boundary (TC-AMZ-004, 006)
  • Accessibility (WCAG 2.1 AA) — keyboard-only navigation, screen reader labels on sign-in (TC-AMZ-007, 008)
Out of scope: Checkout and payment, account creation, product detail pages (REQ-AMZ-05, draft), mobile apps, performance and security penetration testing.
Test Approach
Risk-based black-box testing of the production site as an anonymous and signed-in customer.
  • Functional & positive — core journeys complete as specified
  • Negative — invalid credentials, unmatched search queries
  • Boundary (BVA) — cart quantity limits
  • State — cart contents persist across sessions
  • Accessibility — keyboard operability and programmatic labels (WCAG 2.1 AA)
  • Automation (v2) — Playwright (TypeScript) regression checks for non-authenticated flows, executed locally and in GitHub Actions CI
Environment
Manual: macOS Tahoe 26 · Chrome (latest) · VoiceOver
Automation: Playwright v1.63 · Chromium · local (macOS) and GitHub Actions (Ubuntu)
Target: Amazon.com production (US storefront)
Test Data
  • Dedicated test account (credentials not published)
  • Valid search query: Logitech MX Master 3S
  • Unmatched search query: zxyvwk123456789
Risk Areas
  • High: Authentication — failed or insecure login blocks every downstream journey
  • High: Accessibility — inaccessible sign-in excludes keyboard and screen reader users
  • Medium: Search — irrelevant or empty results reduce product discovery
  • Medium: Cart state — lost cart contents between sessions
Constraints
Testing targets a live third-party production site. Behaviour can vary by session, location, and network origin (see AMZ-OBS-001). Bot detection blocks automated sign-in, so authenticated flows remain manual in v2. Deviations are logged as observations; no developer triage is available.
Exit Criteria
100% of in-scope test cases executed with evidence; every requirement traced to at least one test case; all deviations documented in Bug Reports; automated checks passing in CI.
Deliverables
  • Requirements Traceability Matrix (RTM)
  • Manual Test Cases & Execution Log
  • UI Automation (Playwright)
  • Defect & Observation Log
Future Scope (v3)
  • Automate authenticated flows using Playwright storageState with a dedicated test account
  • Define and test REQ-AMZ-05 (product detail accuracy)
