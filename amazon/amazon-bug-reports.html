AMZ-OBS-001: Empty Search State Inconsistent Across Network Origins

Observation
Type
Observation — Intentional Product Behavior
Severity
Low
Priority
Low
Summary
Search behavior for queries with no organic results is inconsistent. From a residential network, Amazon displays only sponsored fallback products under a "More results" heading, with no "no results" message (Variant A). From a cloud CI environment (GitHub Actions), Amazon displays a "No results for your search query." heading before the sponsored fallback (Variant B). Variant A deviates from REQ-AMZ-03, which specifies a "no results" message with fallback suggestions.
Steps to Reproduce
  1. Navigate to Amazon.com homepage.
  2. Enter a non-existent, random alphanumeric string into the search bar (e.g. zxyvwk123456789).
  3. Submit the search.
  4. Observe the results page.
Expected Result
A "No results found" message displayed with graceful fallback suggestions per REQ-AMZ-03.
Actual Result
No organic results returned. System displays sponsored fallback products with no "no results" message. Amazon does not surface a true empty state — this appears to be a deliberate product decision to maximize ad inventory visibility.
Linked Requirement
REQ-AMZ-03
Linked Test Case
TC-AMZ-005
QA Recommendation
No action required — this is intentional product behavior. Requirement REQ-AMZ-03 should be updated to reflect Amazon's actual empty state handling if this audit were to be formally delivered. Logged here for traceability and documentation completeness.

AMZ-OBS-002: Sign-In Flow Reveals Whether an Email Has an Account

Observation
Type
Observation — Security / Requirement Deviation (Account Enumeration)
Severity
Low
Priority
Low
Summary
Amazon's sign-in uses an email-first flow. Submitting an email with no account displays "Looks like you're new to Amazon" with a prompt to create one, while an email with an existing account proceeds to the password screen. The difference reveals whether an account exists for any email address, which deviates from REQ-AMZ-02's requirement for non-revealing responses that prevent enumeration.
Steps to Reproduce
  1. Open the Amazon.com sign-in page in a private window (signed out).
  2. Enter an email with no Amazon account (e.g. heatqa.noaccount.2026x@gmail.com) and click Continue.
  3. Observe the response.
  4. Return to the sign-in page, enter an email with an existing account, and click Continue.
  5. Compare the two responses.
Expected Result
Per REQ-AMZ-02, the response should not reveal whether an account exists for the submitted email.
Actual Result
Unregistered email: "Looks like you're new to Amazon — Let's create an account using your email." Registered email: proceeds to the password screen. Account existence is disclosed before any password is entered.
Linked Requirement
REQ-AMZ-02
Linked Test Case
TC-AMZ-002
QA Recommendation
Email-first sign-in is a deliberate design choice used by many large platforms; it trades enumeration resistance for usability. If this audit were formally delivered, REQ-AMZ-02 should either be revised to reflect the accepted design, or the enumeration risk should be formally accepted by the product owner. TC-AMZ-002 remains valid for its scope (an incorrect password is rejected), but does not verify the enumeration clause of REQ-AMZ-02.
