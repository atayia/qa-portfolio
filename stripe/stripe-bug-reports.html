STR-OBS-001: Charges API Rejects Card Tokens Despite Documentation and Policy Setting

Observation
Type
Observation — Documentation vs. Behavior Discrepancy (API Deprecation)
Severity
Medium — Charges API card-token flow unusable; documented replacement (PaymentIntents) works
Priority
Low
Summary
The Charges API rejects Card Token usage with an EOL error. Stripe's own documentation states that enabling Card Token support via the API Policies settings page (dashboard.stripe.com/settings/developers/api-policies) should allow continued usage. However, enabling this policy and regenerating the API key had no effect — the EOL error persisted across all attempts.
Steps to Reproduce
  1. Create a Stripe test account and obtain a test secret key.
  2. Send POST /v1/charges with source: tok_visa, amount: 1500, currency: usd.
  3. Observe HTTP 400 error: "Card Token usage on the Customers API and Charges API has reached end of life."
  4. Navigate to Stripe Dashboard → Settings → Developers → API Policies.
  5. Enable Card Token support and save.
  6. Regenerate a new test secret key.
  7. Re-send the same request with the new key.
  8. Observe the same HTTP 400 EOL error persists.
Expected Result
Per Stripe's Older payment APIs documentation, the Charges API "remains available" for existing integrations. After enabling Card Token support in API Policies, POST /v1/charges with source: tok_visa should return HTTP 200.
Actual Result
HTTP 400 · Card Token usage on the Customers API and Charges API has reached end of life. Error persists after enabling the policy setting and regenerating the API key. Stripe's own suggested remediation had no effect.
Linked Requirement
REQ-STR-03
Linked Test Cases
TC-CH-001, TC-CH-002
QA Recommendation
Migrate Charges API test cases to use the PaymentIntents API (POST /v1/payment_intents) with pm_card_visa as Stripe recommends. Charge creation via PaymentIntents is already verified in TC-PI-001. The Charges API with Card Tokens is effectively deprecated for new test accounts regardless of policy settings.
